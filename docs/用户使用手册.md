# 加工厂 ERP · 用户使用手册

面向业务与现场人员：讲清**谁用哪一端、怎么登录、日常怎么操作**。  
开发部署细节见 [README.md](../README.md)；管理端交付边界见 [ADMIN_DELIVERY.md](./ADMIN_DELIVERY.md)。

---

## 1. 系统是什么、有哪几个入口

本系统覆盖木薯粗加工等场景：**采购过磅 → 质检入库 → 工序过站计件 → 仓管 → 销售发货 → 财务**，并配套人事工资与审批。

| 入口 | 给谁用 | 地址（开发默认） | 主要干什么 |
|------|--------|------------------|------------|
| **员工 App（Flutter）** | 过磅、质检、仓管、计件工、班组长 | 手机安装；连 API `http://<电脑IP>:18080/api/v1` | **现场录入**（过磅、过站、入库确认、今日工钱） |
| **管理后台 Admin** | 管理员、计划、财务、人事、销售内勤 | 浏览器 `http://127.0.0.1:5173` | 配置主数据、查询、结算、审批、销售/财务 |
| **老板驾驶舱 Boss** | 老板、管理层 | `http://127.0.0.1:5177` | 看经营看板、关键指标 |
| **门户 Portal** | 选端入口 | `http://127.0.0.1:5170` | 跳转 Admin / Boss；**不做现场录入** |
| **后端 API** | 所有前端共用 | `http://127.0.0.1:18080` | 登录与业务接口 |

**重要约定（产线试点）**

- 现场扫码过磅、工序过站、仓管待入库确认 → **只在员工 App 做**。
- 管理后台对这些现场单据以**查询 / 配置 / 结算**为主，不要当现场终端用。

## 2. 第一次怎么跑起来（开发演示）

在一台已装好 Go / Node / Flutter 的电脑上：

### 2.1 启动后端（必须先开）

```powershell
cd D:\workplace\ycwl-erp-master
go run ./cmd/erp-api
```

看到服务监听 `:18080` 即可。首次会自动建 SQLite 库：`data/erp_dev.db`，并写入演示数据。

健康检查（可选）：

```powershell
curl http://127.0.0.1:18080/api/v1/health
```

### 2.2 启动管理后台

```powershell
cd D:\workplace\ycwl-erp-master\web
npm install
npm run dev:admin
```

浏览器打开：**http://127.0.0.1:5173**

### 2.3 启动员工 App

手机与电脑同一局域网，把 `<电脑IP>` 换成实际 IP（如 `192.168.1.29`）：

```powershell
cd D:\workplace\ycwl-erp-master\mobile
flutter pub get
flutter run --dart-define=API_BASE=http://<电脑IP>:18080/api/v1
```

模拟器可用 `http://10.0.2.2:18080/api/v1`（Android）或本机 `127.0.0.1`。

### 2.4（可选）老板端 / 门户

```powershell
cd D:\workplace\ycwl-erp-master\web
npm run dev:boss     # :5177
npm run dev:portal   # :5170
```

## 4. 按角色：我该用什么

| 你的岗位 | 主要用 | 日常第一件事 |
|----------|--------|--------------|
| 采购 / 过磅员 | App「收货」 | 建过磅单、填净重/扣损、提交 |
| 质检 | App「收货」 | 对过磅单做质检、确认推仓 |
| 仓管 | App「仓管」 | 扫溯源/箱码核对并入库 |
| 计件工 / 固定工 | App「过站」+「我的」 | 扫工牌+箱码过站；下班看今日工钱 |
| 车间主任 | App「过站」「班组」 | 过站复核、返工/异常派岗 |
| 计划 / 管理员 | Admin | 工序定义、工艺流程、班次、任务单 |
| 销售内勤 | Admin「销售管理」 | 客户、锁价、订单、预发货、发货 |
| 财务 | Admin「财务管理」 | 凭证、核销、月结、报表 |
| 人事 / 薪资 | Admin「人事」「工资」 | 员工、考勤、工序工价、核算 |
| 老板 | Boss | 看经营与生产看板 |

多角色账号可在 App 右上角切换角色。

## 5. 产线主流程（必会）

下面按**真实一天**的顺序说明。建议用演示账号各走一遍。

```text
农户到厂过磅(App采购/质检)
    → 出箱码/溯源、推仓管
    → 仓管核对入库(App仓管)
    → 车间按工艺工序过站(App工人)
    → 「我的」核对今日计件
    → （内勤）销售订单与发货、财务结算(Admin)
```

### 5.1 过磅收货（App · 采购 / 质检）

1. 用 `u_purchase` 或 `u_qc` 登录 App。  
2. 底部进入 **收货**。  
3. **新建**（入厂 / 入库模式按现场选择）：
   - 选择或搜索农户、品种；
   - 录入毛重、扣损率等，系统算净重；
   - 可拍照/填溯源相关信息（演示可手输）。  
4. 提交后，质检侧做确认 / 扣损；通过后 **出码并推送仓管待办**。  
5. Admin 侧可在 **采购管理 → 过磅收货 / 农户 / 结算** 查询与配置，**不要替代 App 现场建单**。

### 5.2 仓管入库（App · 仓管）

1. `u_warehouse` 登录 → **仓管** → **待入库**。  
2. 扫溯源码或输入批号定位单据。  
3. 核对重量、照片后点 **核对相符并入库**。  
4. 其他页签：库存、箱码、盘点、出入库（按现场需要使用）。

### 5.3 工序过站与计件（App · 工人）

1. `u_piece` 登录 → **过站**。  
2. **工牌码**填 `EMP-PC`（首次会记住）；**箱码**扫或手输。  
3. 填投料重、完工重（装袋工序填袋数）；需要时选次品类型。  
4. 建议先点 **预览**，再 **提交草稿**，最后 **确认过站（QC 合格）**。  
5. 卡点工序若 QC 不合格，选阻断，系统不会错误过账。  
6. 打开 **我的**：查看 **今日产量与工钱**，点刷新核对。

箱码随过站推进工序；下一道工序继续扫同一逻辑下的新箱码（界面会提示）。

### 5.3.1 在管理端维护工艺流程（管理员）

1. 登录 Admin → **生产管理 → 工艺流程**。
2. 打开「木薯丁产线」或新建生产类流程图。
3. 拖拽工序节点、连线（默认路径会参与编译）。
4. 可绑定产品；保存为**草稿**不会改现场过站步骤。
5. 确认无误后点 **发布**：系统把默认路径编译进 工艺步骤，过站 App 按序推进。
6. 左侧「已编译步骤」可核对序号、计件、卡点标志。

### 5.4 班组异常（App · 主任）

1. `u_foreman` 登录 → **班组**。  
2. 处理返工派岗、质检废料等异常（非「每箱派工」）。  
3. 日常过站仍在 **过站** Tab。

### 5.5 销售闭环（Admin · 销售）

用 `u_sales` 或 `admin` 登录管理后台：

1. **客户管理** → 维护客户。  
2. **销售管理 → 锁价 / 报价**（如有）：先锁价再下单更稳妥。  
3. **销售订单**：新建订单 → 提交。  
4. **预发货 → 发货审批** → 状态到已发货。  
5. 需要出厂结算时用 **出厂结算** 页。  

（销售外勤默认不在 App 底栏；内勤以 Admin 为主。）

### 5.6 财务日常（Admin · 财务）

用 `u_finance` / `admin`：

1. 维护科目、资金账户。  
2. 录流水 / 凭证（借贷需平衡才能过账）。  
3. 核销、认款、预收预付。  
4. **月结**后当期不可再随意改账。  
5. 生成三表等报表前，先完成过账与「生成报表」类操作。

## 6. 管理后台怎么逛菜单

登录 Admin 后，左侧为业务域。标 **未上线** 的为占位，勿当生产功能用。  
产线试点 + 财务/人事/系统等已上线模块可正常点开。

### 6.1 与产线强相关

| 菜单（示例） | 做什么 |
|--------------|--------|
| 采购管理 / 过磅、农户、品种、结算 | 查询过磅与农户档案；配置品种 |
| 采购管理 / 过磅流程编排 | 入厂/入库审批流程画布 |
| 生产管理 / 工序定义 | 工序主数据、是否计件 |
| 生产管理 / 工艺流程 | 产线流程图：草稿只存图；**发布**后才编译为过站步骤。可绑定产品。左侧可预览已编译步骤。节点名应为中文；若见问号可重启 API 触发修复 |
| 生产管理 / 产线班次、任务单 | 班次授权、生产任务 |
| 生产管理 / 过站记录、计件工资 | 查询现场过站与计件（现场录入在 App） |
| 库存管理 / 入库、结存、箱码 | 库存与箱码查询 |
| 工资管理 / 工序工资 | 计件单价 |

### 6.2 经营与内勤

| 域 | 典型用途 |
|----|----------|
| 销售管理 | 订单、询价、预发货、发货、合同锁价、出厂结算 |
| 客户管理 | 客户档案、跟进 |
| 产品管理 | 物料/成品主数据 |
| 固定资产 | 设备台账 |
| 统计报表 | 经营/生产看板 |
| 审批管理 | 待办审批 |
| 系统管理 | 用户角色权限、工单中心、业务闭环、日志 |

权限不足时菜单可能看不到或操作失败：用 `admin` 在 **人事/系统 → 角色权限** 中授权。

## 10. 常见问题

**Q：页面上工艺名称全是问号？**  
A：多为 Windows 演示库历史乱码。重启一次 `erp-api`（启动会自动修复演示路线）；仍不对可执行：  
`go run ./scripts/repair_flow_encoding.go data/erp_dev.db`  
然后硬刷新浏览器。

**Q：Admin 打不开、一直转圈？**  
A：先确认 API 已在 18080 运行；浏览器访问 `http://127.0.0.1:18080/api/v1/health`。Web 需用 Node 20+（推荐）。

**Q：App 登录失败 / 连不上？**  
A：手机与电脑是否同一 Wi‑Fi；`API_BASE` 是否写成电脑局域网 IP（不要用电脑的 `127.0.0.1` 给真机）。

**Q：为什么 Admin 不能录过站？**  
A：产品设计：现场只在 App。Admin 过站页默认只读。

**Q：菜单显示「未上线」？**  
A：该模块尚未纳入当前交付范围，勿用于正式业务。

**Q：忘记密码？**  
A：演示环境统一 `admin123`。正式环境请管理员在系统管理中重置。

**Q：键盘挡住过站输入？**  
A：已弱化页眉；请上滑列表。仍挡可横屏或收起键盘后再确认。
